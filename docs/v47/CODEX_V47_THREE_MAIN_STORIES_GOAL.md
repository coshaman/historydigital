# Codex Goal V47 — 1848~49 상트페테르부르크의 3개 메인 사건을 '실제로 플레이 가능한' 역사 RPG로 구현

## 최종 목표
사용자가 제안한 3개 메인 이벤트를 기존 `coshaman/historydigital`의 도트 RPG·빙의·자율 NPC·Vercel AI 대화·큰 문서 열람기·직업/경제 시스템에 합친다.

- **MAIN01**: 1848년 실제 배포 금지된 《삽화 연감》(Иллюстрированный альманах) — 한 차례 검열 허가, 인쇄, 재심사, 금지·폐기 명령, 구독자 보상, 노동자 급료, 편집자와 작가의 갈등.
- **MAIN03**: 1848년 유럽 혁명 뉴스와 검열 강화 → 1849년 페트라솁스키 금요일 모임 → 정보원·경찰 감시 → 1849년 4월 23일 체포 → 역사적 후일담. 농노제·종교·사회주의·푸리에주의·서구주의·표현의 자유를 장면 속 살아 있는 이견으로 다루고 실제 경찰·학생·정보원·서기를 빙의 가능한 서로 다른 시점으로 만든다.
- **MAIN05**: 1848년 상트페테르부르크 콜레라 유행. 수원·음식·가족·진료·병상·경제·군중·소문의 동적인 인과 모델과 여러 신분별 생활 퀘스트를 결합한다.

**이 작업은 문서/테스트만 작성하고 종료하면 실패다.** 반드시 실제 지도·NPC 애니메이션·퀘스트·대화·독서기·상태 전이·인게임 분기·저장까지 구현하고 브라우저 화면에서 확인한다. 기존 5가지 엔딩·로컬 fallback·Vercel Functions를 깨뜨리지 않는다. 실제 실행 못 한 검사는 PASSED로 쓰지 않는다.

## 우선 읽을 입력

프로젝트의 `AGENTS.md`, `package.json`, `vercel.json`, `rpg/main.js`, `rpg/engine/game-state.js`, `rpg/engine/historical-session.mjs`, `rpg/engine/dialogue-context.mjs`, `rpg/engine/dialogue-response.mjs`, `rpg/engine/renderer.js`, `rpg/engine/quest-guidance.mjs`, `rpg/data/historical-source-packets.json`, `rpg/data/source-reader-index.json`, `rpg/data/case-contexts.json`, `rpg/data/v38-historical-events.json`, `rpg/data/historical-scene-play.json`, `rpg/data/historical-conversation-choices.json`와 `rpg/characters/`·`rpg/maps/`·`rpg/quests/`의 실제 스키마/관계부터 확인하라.

이 번들 파일:

- `scenarios/MAIN01_banned_illustrated_almanac.md` (~19k자)
- `scenarios/MAIN03_revolution_friday_and_arrests.md` (~19k자)
- `scenarios/MAIN05_cholera_living_city_1848.md` (~19k자)
- `data/SCENARIO_EVENT_GRAPH.json` (36개 사건 비트 / 아직 구현 전 시드)
- `data/INTEGRATED_WORLD_CHRONOLOGY.json` (세 스토리가 하나의 달력에서 어떻게 겹치는지)
- `sources/SOURCE_REGISTRY.csv`, `sources/SOURCE_REGISTRY.json` (26개 자료 조사 출발점)
- `sources/QUOTE_SEEDS.json` (실제 자료에서 확인한 짧은 원문과 한글 번역 — 직접 인용 단위)
- `data/CHARACTER_SCENARIO_CONTEXTS.json` (30개 인물 역할 정의, 중복되는 인물은 동일 생애·기억 공유)
- `qa/validate_bundle.py`, `qa/VALIDATION_REPORT.json`

이 자료는 **설계 시드**이며 완성된 게임 런타임 데이터가 아니다. 1848년 6월 콜레라 사건들의 세부 날짜/동선, 인쇄소 대화 등은 역사적 현장 전사를 주장하지 않는 허구다. 역사 입증 레벨을 상향하려면 원본 텍스트/이미지/페이지/원전 지위를 정확히 확인해야 한다. 본편에는 `허구 재구성`, `근거 수준`, `AI 생성`, `구현 목표` 같은 개발 문구를 표시하지 말고, 출처·판본 확인 기능은 선택형 자료철로 남겨야 한다.

## 아키텍처 결정을 먼저 내려라 (리라이트 금지)

기존 RPG의 `gameState`와 시뮬레이션/저장/빙의 함수를 재사용하라. 거대한 새 프레임워크를 도입하지 않는다. 다음의 **단일 정본**을 연결한다:

```text
historical source registry → source excerpt / document reader
                             ↓
world calendar → deterministic event schedule → event state → quests + NPC goals
                                                       ↓
player possession → character-specific knowledge/access → scene-specific interactions
                                                       ↓
           authored opening + option lists ← AI NPC dialogue (server, bounded)
                                                       ↓
               player choice/action → authoritative world reducer
                                                       ↓
             world event callbacks → newspaper updates + household consequences
                                                       ↓
                 5 기존 엔딩의 실제 기록·사회 관계에 반영
```

`AI`는 자유 발화·대화 자연스러운 연결·인물별 반응을 생성하되, 새 인물의 역사적 사실을 invent하거나 검열 날짜·체포·콜레라 수치·사망 결과·퀘스트 완료·돈·스탯·사료 원문을 바꾸지 못한다. `/api/rpg/dialogue`는 Vercel 서버측 `OPENAI_API_KEY`만 이용한다. 라이브 호출은 기존 안전한 키/프로젝트가 준비돼 있으면 소수만, 주요 QA는 mock과 완전한 오프라인 authored fallback으로 한다. 공개 프런트 코드·로그·ZIP에 키나 비밀값을 포함하지 않는다.

## PHASE 0 — 현재 저장소 회귀 기준과 역사 연표

1. 작업 시작 전 실제 HEAD SHA, 빌드 명령, 기존 5엔딩 smoke, Vercel Functions/Redis 상태, 현재 지도 및 NPC 행위 리스트를 인벤토리로 기록한다. 정상 작동하는 기능을 보존할 단위 테스트를 먼저 고정한다.
2. 1848~1849년 시나리오의 핵심 8개 앵커를 `WORLD_EVENT_ANCHORS`로 만들고 러시아 제국의 구력(율리우스력)과 해외 자료의 신력(그레고리력)을 별도 필드로 표기한다. 원자료가 구력인지 확인되지 않으면 확정할 때까지 `UNVERIFIED_CALENDAR`로 둔다. 절대 `1848-10-20` 하나를 서로 다른 달력의 동일 날짜로 섞지 않는다.
3. 이미 구현한 사건을 복사해서 중복 실행하지 않는다. `1848` 콜레라·검열과 `1849` 체포 사건이 `rpg/data/v38-historical-events.json` 등에 있는지 확인하고 `reuse|extend|replace` 매핑표를 만든다. 플래그/동일 ID/명칭이 충돌하면 어댑터로 정규화하라.

**Exit:** 실제 상태·구현 경로가 확인되고, 날짜가 명확한 사건은 미래 자료가 과거에 노출되는 통로가 없다.

## PHASE 1 — 사료 검증 파이프라인을 먼저 게임 데이터에 연결

**문서의 실체를 강제한다.** `sourceId`, `titleRu`, `titleKo`, `author`, `createdAt`, `approvedAt`, `publishedAt`, `laterEditionAt`, `accessibleToPlayerAt`, `eraCalendar`, `sourceRole`, `edition`, `issuePageFolio`, `url`, `scanUrlIfVerified`, `verifiedShortQuote`, `quoteExactness`, `koTranslation`, `license`, `readabilityState`를 실제 데이터에 넣고 임의의 `DIRECT`는 차단한다. 후대 연구·논문·현대 의학 정보는 game engine 및 별도 출처창에서만 쓰고, 당시 주민의 수중 문서로 자동 출현시키지 않는다.

- MAIN01의 실제 검열 대상은 「호리와 칼리니치」를 검열 때문에 뺐다는 가상 추측이 아니라 **1848년 인쇄된 《삽화 연감》 그 자체**다. 주요 작품은 아브도티야 파나예바의 「탈니코프 가족」, 도스토옙스키의 「폴준코프」 등이다. 원본/영인본에 실제로 들어 있는 장/페이지를 확인한 다음 큰 독서기에 제공. 역사적으로 2월 26일에 한 차례 허가, 10월 20일 배포 금지와 폐기 명령, 11월 17일 구독자 편지라는 흐름을 지켜라. 검열관이 책의 성격을 문제 삼았다는 실제 후대 회고는 `MEMOIR_LATER`로 취급하고 1848년의 속기 기록처럼 사용 금지.
- MAIN03의 페트라솁스키 소사전/벨린스키 편지는 실제 판본·필사본·정당한 열람 경로가 있어야 한다. 안토넬리 1849년 5월 이후 보고를 4월 15일 참석자에게 보여주거나 벨린스키를 1849년 생존자로 등장시키지 않는다. `GARF` 현대 설명과 архив의 실제 문서 원문은 분리한다.
- MAIN05의 1848년 런던에서 나온 크로퍼드 보고서는 **1848년 8월 말 이후/문헌의 실제 출판·도착 이후에만** 독서기에 나온다. 1848년 6월 의사가 `1854년 존 스노 우물 조사`나 `1883년 병원체 규명`을 언급하는 것은 P0 오류다. WHO/CDC 자료는 내부 질병 모델링에만 사용.
- 사료 텍스트가 충분치 않은 경우 남의 시대에 쓴 문장으로 채우지 말고 간행 사실·표지·목차 등 신뢰되는 정보만 우선 제시, 추가 발췌의 검수 상태는 `PENDING`이다.

**Exit:** 세 메인 이야기의 핵심 source packet 최소 각 4종 이상이 실제 자료철에 존재하고, 실제 플레이에서 열람 가능한 문서 2종 이상/시나리오, 원문과 번역의 1:1 대응. 총 source registry 26행은 수집 **출발점**이고 26종이 모두 독립 원전이라고 주장하지 않는다.

## PHASE 2 — 세계에 사건이 눈앞에서 벌어지는 EventDirector 구현

기존 시계와 NPC 상태기계를 재사용해 `EventDirector`를 구성한다.

- 이벤트 정의: `id, era, earliestAt, deadlineAt, prerequisites, sourceIds, publicWorldFacts, secretWitnessFacts, involvedCharacterIds, mapIds, stage, actionPoints, NPCGoals, mutableOutcomeFlags, immutableHistoricalAnchor, nextTransitions, offscreenResolution, onScreenScene`.
- MAIN01의 **인쇄소에서 실제 인쇄·운송·압수·창고이동**, MAIN03의 **모임에 입장·감시·경찰 분대 이동·체포·문서 압수**, MAIN05의 **수원·진료·여관 폐쇄·이주·군중 행동**은 NPC가 실제 경로로 이동하고 장소/물건/주민 상태를 변경해야 한다. “~사건이 일어났다”라는 작은 텍스트로 끝내면 FAIL.
- 사용자가 어떤 사건을 열지 않아도 NPC는 사건에 도착해 참여한다. 플레이어가 나중에 빙의하면 기존 사건의 진행 상태를 이어받지, 새로 0부터 반복하지 않는다.
- 동일한 주민은 세 사건에서 하나의 집·가족·주거지·직업·관계·지식을 가진다. 사본 인쇄물, 콜레라의 부채, 1849년 수사 동선이 서로 다른 장에서 기억으로 돌아온다.
- 타임라인 중 1848년 콜레라가 연감 인쇄 진행 중 발생한다. '1848년 콜레라 클리어 → 1848년 2월로 돌아가 연감 인쇄' 같은 시간 역행이 기본 게임 상태에서는 불가능해야 한다. 2월 시작 허가/인쇄 파트는 초반 이벤트, 6~8월 콜레라 중단, 10월 금지와 11월 후일담, 1849년 감시와 체포로 이어진다. 필요시 시간 기록이 분리된 문학체험/회고 씬임을 engine에 명시한다.

**Exit:** 각 시나리오 12 비트(`36` 총 비트)를 실제 작동하는 EventDirector 상태에 매핑. 최소 3개씩의 이벤트를 사용자 무개입 24h sim과 NPC 시야에서 재현. 실제 지도/물건/장부/신문 상태 변화 PASS.

## PHASE 3 — 빙의 중심 퀘스트·대화·사회 상호작용

각 시나리오 10개 이상의 고유 관점(정확히 10명에 대한 600자+ 설계가 이미 있다) 중 **각 6명 이상을 실제 조종해서 다른 상호작용을 완료할 수 있어야 한다.** 가상 주민 36명의 전체 일과 유지와 별개로 이 3개 주요 사건의 핵심 역할은 사건마다 8~10명이다.

- 모든 메인 퀘스트는 **무엇을 알게 되었는지, 지금 해야 할 일 1개, 가야 할 위치 또는 인물, 이유, 완료 조건, 예상 후속**을 수첩에 기록한다. '독서/대화 5번 클릭' 같은 횟수 기반 퀘스트 금지. 일반 NPC의 집·상점·일자리·돈·휴식은 자유롭게 이용 가능하고, 여러 인물에 빙의해 필수 증거를 서로 다른 방식으로 얻을 수 있다.
- `opening intention → scene encounter → contextual dialogue → document or physical evidence → real action → reaction and journal update` 구조를 사용. 처음 만난 서점 손님에게는 “무엇을 찾으세요?”부터 묻고, 이미 관계가 있는 둘에게는 지난 사건과 감정 변화가 드러나게 한다.
- 중요한 선택은 **줄거리 분기나 시점 변화가 있는 지점**에만 2~4개 제시. 모든 대사 뒤 3개 선택지 강제 금지. 직접 자유 입력은 대화 용도, 행정적인 세계상태 변경은 검증된 행동 선택지/오브젝트 상호작용만 허용.
- AI 대화 서버에 현재 인물의 말투·계급·다른 인물과의 관계·직접 들은 발언·읽은 글·지금 필요한 목적·모르는 정보를 전달하라. AI는 저질 해요체 반복, NPC가 제한 사항을 낭독하는 문장, 공허한 철학 일반론을 쓰면 재생성/author fallback. 불확실한 자료는 질문을 돌리거나 ‘모른다’고 인간다운 방식으로 말할 수 있지만 “저의 알고리즘 제약상…” 같은 메타 언어는 0건.
- 감정은 말투뿐 아니라 일과 변화로 드러나야 한다. 안나가 임금을 못 받으면 다음 날 다른 일자리를 찾아 움직이고, 경찰에게 오인 체포당한 허구 학생의 하숙집에는 빈 침대가 남으며, 환자가 회복하면 병실이 비어 다음 주민이 들어온다.

**Exit:** 각 3개 메인 퀘스트의 실제 시작→중간 조사→분기→후폭풍 UI 경로. 최소 사건별 다른 빙의자 3명 이상의 UI replay, 핵심 조사 비트는 다른 행동 대체 루트 1개 이상.

## PHASE 4 — 각 장의 고유 게임 시스템

### MAIN01: 인쇄된 책이 왜 없나
- 실제 연감 원본·삽화에 근거한 **활자 조판 / 교정쇄 문장 대조 / 금지 전후 날짜 퍼즐 / 구독 예약·임금·배송** 구현. 단순 UI 텍스트 버튼 4개로 모든 미니게임 처리한 척하면 실패.
- 타임라인 상 10월 20일 **실제 배포 금지**는 변하지 않지만 노동자의 임금·비밀 보관 사본·서점 평판·구독자 응답·1849년 수사 관련 배송망은 분기한다.
- 작중 이념 질문은 ‘가정 폭력 묘사/부모 권위/출판의 자유/작가의 책임’처럼 연감의 실제 검열 문제에 붙인다. 「탈니코프 가족」 판본을 확보하지 못했다면 실제 문장처럼 보이는 허구 인용을 만들지 마라.

### MAIN03: 철학 모임과 감시·체포
- 1848년 유럽 혁명 뉴스와 1849년 금요일 모임을 `world clock` 기준으로 이어 붙여라. **서구주의/슬라브주의/푸리에주의/종교와 정치/농노제와 소유/표현의 자유**에 대해 같은 사료를 읽은 뒤 서로 다른 신분이 실질적인 논거로 대화한다.
- 정보원은 **가까이에서 듣고 본 사실만** 보고한다. `NPC Sicht`·문·소리·목격/전달 경로와 기존 엔진의 충돌·pathfinding을 재사용한다. 실제 인물의 극중 속마음과 경찰의 공식 보고를 혼동하지 않는다.
- 1849-04-23 체포는 중요한 동적 현장. 경찰 NPC 출동, 학생/하숙집 주민의 이동, 물건 압수/보관, 선택적 도주/목격/침묵과 체포 후 조사가 모두 실행된다. 실제 피체포자 결과를 임의로 없애는 영웅 서사를 만들지 않는다. 후대 보고는 이후에만 제공한다.

### MAIN05: 전염병이 도시를 바꾸는 과정
- **모델 개발용** `S/E/I/R/D` (건강한 주민/노출/감염 진행/회복/사망), 수원/음식 공급·주거/가족 접촉·환자 이송·진료/돌봄·사망/이주·소문과 가게 폐쇄를 연결. 환자와 비환자 매칭만의 단순 랜덤 3문항 퀴즈 금지.
- 감염 경로는 현대 과학에 맞게 **오염된 물·음식**이 우선이며, 같은 타일에 있다고 공기 전염된다는 규칙 금지. 수학적 파라미터는 사료에서 보정되지 않았다면 **가상 디자인 값**임을 내부 개발 문서에 표시. 영양·건강·계급·의료 접근권·돌봄과 경제적 약자를 함께 모델링하되 특정 계층 전체를 불가피한 피해자로 고정하지 않는다.
- 당시 의사는 존 스노의 **1854년 연구**나 콜레라균의 **1883년 동정**을 미리 알지 못한다. 역사적 치료 관행을 의학적으로 효과 있는 현대 가이드로 표시하지 않는다. 1848년 **8월 이후** 출간된 Crawford 보고서를 그해 6월 환자 앞에서 낭독하지 않는다.
- 지나친 처벌용 사망 루프를 금지한다. 위기 시 위험을 줄이는 여러 역사적으로 가능한 돌봄/급수/동선 선택지가 있어야 한다. 시뮬레이션 재현 시드로 무개입·급수 변경·병상 증설·소문 악화 네 실험에서 의미 있는 차이가 나와야 한다.

**Exit:** 세 시스템 모두 실제 화면/상태/고유 퀘스트/게임 내 후폭풍 존재. 수치만 변화한 로그나 ‘정보 카드가 나왔다’만 있는 구현을 미완성 처리.

## PHASE 5 — 거대한 자료 열람기와 '눈앞에 일어나는' 연출

- 기존 큰 문서 독서기를 확장해 연감 **책·목차·삽화·구독자 편지**, 정치 **소사전·필사본·수사 자료·신문**, 질병 **의사 기록·주민 장부·병원 상황판·일기**를 각각 맞는 재질/타이포/페이지 구성으로 렌더링한다. 원문 RU와 한글 번역은 해당 excerptId가 맞아야 하고 번역이 다른 문서에 반복 나오면 FAIL.
- 대화/퀘스트 UI가 항상 화면 아래 스크롤에 묻히지 않도록 desktop·mobile 모두 viewport 내 game shell, 읽기 모드에서만 내부 세로 스크롤 허용. 옆에 큰 책이 펼쳐졌다면 NPC/선택창은 닫거나 축소. 360×800 모바일 선택지 44px 이상 터치, 읽는 도중 팝업 가림 금지.
- NPC 이동·캐리어·임시 경찰·환자 수레·활자·교정쇄·시장 가격표·닫힌 가게·경비 초소 등 사건 전후 바뀌는 scene props를 실제 에셋으로 구현한다. 지난 V36~V38 자산을 점검하고 부족한 부분만 추가. CSS 원·사각형으로 시대 이미지를 대신하지 않는다.
- 자연스러운 대화는 **사람을 만나는 것으로 시작**하며 어느 인물이 무엇을 원하는지 플레이어가 점차 알아가게 한다. `선택값`, `허구 설정`, `역사적 경계`, `메인 목표`, `AI 제약` 같은 개발 용어는 본편 HUD/대사에서 0건. 자료철의 서지와 접근성 도움말은 접근 가능하게 유지.

## PHASE 6 — 실측 검증과 복원 가능한 패키징

1. 각 시나리오 **첫 플레이**와 **최소 한 가지 다른 빙의/선택 경로**를 브라우저 UI로 완주. 각자 30~60분의 설계된 내용을 단순 스킵으로만 테스트하지 말고 문서 읽기·생활·NPC 이동·주요 대화를 실제 이벤트 로그에 남긴다. 예상 플레이시간은 HUMAN 실측 전에는 추정치라고 보고한다.
2. `MAIN01` 허가 2월→금지 10월→회신 11월, `MAIN03` 1849년 4월 체포와 12월 사건, `MAIN05` 6~7월 유행과 8월 이후 기록 등 날짜 기계적 검사. 사건 ID마다 직접 인용·편집 주석·현대 연구 구분. 동시기 접수되지 않은 문서는 늦게 도착해야 함.
3. NPC 자동 14일 무개입 플레이, 플레이어 빙의 3번 변경, 계급과 관계별 지식 변화, 수원 변화/임금 지급/경찰 기록 등 원인-결과 반사실 테스트. 동일 seed replay state hash 일치, 36 NPC와 3개 메인 이벤트 활성화 시 프레임 지연·메모리 누적 측정.
4. 데스크톱 1440×900/1366×768과 모바일 390×844/360×800에서 첫 만남·선택 분기·큰 RU/KO 문서·동적 이벤트·다중 빙의·후일담 실제 픽셀 스크린샷 직접 확인. 첫 화면이 약하고 UI 슬롭이 보이면 두 번째 refinement pass 후 재검수.
5. `npm run build:v33` 또는 현재 실제 배포용 명령, Vercel Functions 세션/API health/mock, 5 기존 엔딩, 저장·불러오기 마이그레이션과 이전 퀘스트 회귀 검증. **Build PASS와 역사 정확성 PASS는 별개**.
6. 변경 전/후 전체 파일, 신규 이벤트 JSON 및 소스 코드, 인물 관계/지식 자료, 이 시나리오 원본(>=8k 각), 출처·판본·번역/권리 상태, 세계 시뮬레이션 seed/trace, 실제 브라우저 스크린샷, 실패 사례 및 해결 로그, API mock/실제 여부가 포함된 ZIP 생성. Clean extract와 hash verify. 미검증은 UNVERIFIED.

## 하네스·서브에이전트 계약

**동시에/전체 최대 2명의 서브에이전트**, 기본 1명(비판적 역사·대사·게임플레이 통합 검토). 이미 다른 대규모 작업에서 다중 에이전트가 성능을 저하했다는 맥락을 존중. 주 에이전트는 콘텐츠 제작과 실제 코드 수정을 담당하며, 검수자는 테스트 로그가 아닌 **실제 PNG·대사·사료·분기 리플레이**를 직접 본다. 두 번째가 꼭 필요한 경우에만 자료 검증/시각 QA를 추가. P0/P1은 실제 수정 후 새로운 자료로 재평가, 미사용이면 reviewer unavailable로 표시. 운영 스크립트 검증을 인간 플레이테스트라 부르지 않는다.

DAG는 단계별 체크포인트: `baseline → source-proof → event-model → vertical-slice-01 → vertical-slice-03 → vertical-slice-05 → multi-possession → visual-perf → regression+citations → packaging`. 먼저 한 장면이라도 실제로 작동시키고 나머지를 대량 복제하지 말 것. 한 phase가 test 실패하면 원인을 고치고 완료된 단계를 불필요하게 다시 설계하지 않는다. **단순 기준 통과 보고서로 구현을 대체하지 마라.**
